# 규모 검증

파일을 생성하거나 원본 디스크를 스캔하지 않고 합성 메타데이터 100만 개와 구조화 데이터 10만 개를 SQLite에 준비합니다. 일반 테스트·CI에서는 실행하지 않습니다. 저장 위치는 테스트용 로컬 SSD 폴더를 사용하세요.

```powershell
dotnet run --project tools/FindEverything.ScaleBenchmark -c Release -- --directory C:\Temp\FindEverythingScale --files 1000000 --catalog 100000
```

같은 DB의 조회만 재측정하려면 `--reuse`를 추가합니다. 빠른 개발 확인은 `--files 2000 --catalog 2000`으로 실행할 수 있습니다. 위치를 지정하지 않으면 시스템 임시 폴더 아래에 새 디렉터리를 만듭니다. 준비한 DB는 재측정을 위해 남기며 경로를 출력합니다.

출력은 첫 500행, 검색 20회의 P95, 순차 20페이지, 선택 3개 조회, 구조화 숫자 정렬·필터 개수, 메모리 수치입니다. 구조화 기본 경로 정렬은 오름차순·내림차순의 첫 500행과 10만 번째 행 근처의 500행도 각각 측정합니다(`CatalogPathDeepOffset`이 실제 위치이며 작은 데이터에서는 마지막 페이지를 사용합니다). UI 렌더링·스크롤이나 실제 디스크 스캔 시간은 포함하지 않습니다. Windows 11·16GB RAM·로컬 SSD의 앱 실행 검증과 함께 사용하며 다른 OS에서의 결과를 Windows 성능 보장으로 해석하지 않습니다.

## 측정 기록

2026-10-13, macOS / .NET 10.0.12, 파일 메타데이터 1,000,000개와 구조화 항목 100,000개를 준비한 DB의 데이터 계층 측정입니다. 합성 데이터는 짧은 문자열 3개와 숫자·날짜 필드를 사용했습니다. 준비 시간은 메타데이터 약 205.5초, 구조화 약 42.4초이며 아래 조회 시간에 포함하지 않습니다. 이 기준 측정 후 추가된 표시용 텍스트 미리보기와 메모 revision 검사는 별도 회귀 테스트로 확인했습니다.

| 측정 | 시간 |
|---|---:|
| 파일 첫 500행 | 70.2ms |
| 파일 검색 P95, 20개 입력 | 222.6ms |
| 파일 순차 20페이지 | 88.6ms |
| 선택 경로 3개 | 107.7ms |
| 구조화 첫 500행 | 30.0ms |
| 구조화 검색 P95, 20개 입력 | 233.5ms |
| 구조화 숫자 역순 첫 500행 | 81.3ms |
| 구조화 필터 개수 | 113.6ms |

조회 후 관리 힙은 약 1.68MB, 프로세스 Working Set은 약 92.6MB였습니다. WPF 화면의 ViewModel·컨트롤·가상화 캐시는 포함하지 않으며, 하드웨어와 데이터 내용에 따라 결과가 달라집니다.
