# FindEverything 프로그램 설명과 요구사항

FindEverything은 Windows의 로컬 디스크와 공유 폴더에서 폴더 경로와 텍스트 파일의 내용을 업무 데이터로 보여주는 앱이다. **구조화 보기**에서 고객·프로젝트·날짜처럼 폴더 구조에 담긴 정보를 검색한다. 업무별 추출 규칙은 프로필로 관리하므로 앱의 탐색 코드와 업무 데이터 구조를 따로 변경할 수 있다. 일반 파일 검색 기능은 코드와 데이터를 유지하지만 현재 단계에서는 **파일 찾기**를 내비게이션과 홈에서 숨긴다.

파일이나 폴더의 이름과 내용은 검색·스캔·프로필 테스트로 변경되지 않는다. 앱은 메타데이터, 추출 결과와 사용자가 직접 입력한 메모를 별도 저장한다.

## 출시 전 사용성·반응성 점검 반영 (2026-10-16)

- 구조화 보기의 검색·실행과 프로필·위치를 두 줄로 유지한다. 진행 상태는 고정 높이 한 줄에서 말줄임하고 전체 내용은 툴팁으로 제공한다. 재스캔 중 이전 표가 남아 있으면 **이전 결과 · 갱신 중**을 표시한다. 처음 진입하면 검색창에 포커스를 두고, 재진입하면 마지막 작업 영역으로 돌아간다.
- 홈에 **프로필 가져오기**를 제공한다. 홈·구조화 보기·공유 메뉴·파일 드롭 모두 실제 설치된 프로필을 선택한다. 교체 확인은 규칙뿐 아니라 JSON에 포함된 출력 포맷·선택 포맷·컬럼 표시 설정이 바뀐다는 점을 설명한다. 기존 스캔 DB는 지우지 않는다. 같은 스키마의 컬럼 설정도 즉시 반영하고, 오래된 화면의 너비 저장이 가져온 설정을 덮어쓰지 않도록 버전을 확인한다.
- 탐색 로그는 페이지 안에서만 공간을 쓰며, 제목·도구 한 줄 / 로그 / 요약 한 줄로 구성한다. 크기 조절 손잡이는 드래그와 위·아래 방향키를 지원한다. 작은 창에서는 복사·저장·지우기를 이름과 툴팁이 있는 아이콘 버튼으로 줄인다. 로그 포커스에서 Ctrl+C는 해당 로그 전체, Ctrl+Shift+C는 경로만 복사한다. 결과 선택용 Ctrl+A/C/V는 결과 표와 선택 도구 영역에만 적용하며 텍스트 편집기의 기본 동작은 유지한다. 복사 실패는 중립 알림으로 안내한다.
- 프로필 마지막 단계의 주 동작은 **저장 후 테스트**, 보조 동작은 **저장**이다. 저장은 항상 검증하며 별도 검증 버튼은 저장 없는 확인 용도다. 오류 이동 버튼과 단계 제목은 같은 3단계 정의를 사용한다. Playground 취소는 경로 정규화·규칙·파일 읽기 사이에 전달하며, 취소된 운영체제 호출이 실제로 끝나기 전에는 두 번째 평가를 시작하지 않는다.
- 폴더 열기와 파일 선택창의 초기 경로 확인은 UI 스레드에서 네트워크 존재 여부를 확인하지 않는다. 초기 위치 확인은 200ms를 넘기면 생략하며 실제 확인 작업은 최대 하나만 유지한다. 운영체제의 네트워크 I/O를 강제로 중단할 수 있다는 의미는 아니다. 출력 포맷 저장·삭제는 백그라운드에서 내구성 있게 저장한 뒤 읽기 전용 메모리 스냅샷을 교체한다. 실패한 저장은 기존 스냅샷과 사용자의 초안을 유지한다.
- 공유 묶음은 검증한 임시 사본을 설치까지 유지한다. 확인 후 원본 파일이 바뀌어도 다시 읽지 않고, 취소하면 임시 사본을 정리한다. 현재 구조화 보기의 내보내기는 선택된 프로필과 구조화 결과를 함께 담는다. 구조화 결과가 없는 메타데이터 전용 묶음은 설치 전에 이유를 알려 거부한다.
- 공유 경로 재연결·언어 변경으로 새 파생 DB가 만들어지면, 이전 `linked-N`은 모든 조회의 사용권이 해제된 후에만 정리한다. 다른 프로세스의 파일 잠금도 확인한다. 현재 버전, 원본 `archive`, 소유 표시가 없는 예전 폴더, 링크나 알 수 없는 파일이 섞인 폴더는 자동 삭제하지 않는다. 정리 실패는 조회를 실패시키지 않는다.
- 숫자·날짜·문자열 정렬은 첫 조회 시 디스크 기반 순서 키를 한 번 만들고 뒤쪽 페이지는 순번으로 조회한다. 선택 결과와 전체 내보내기도 같은 순서를 재사용한다. 첫 정렬 비용은 남으며, 필터·선택·메모·데이터 버전이 바뀌면 이전 순서를 재사용하지 않는다. 값 읽기의 기존 바이트 제한과 취소를 유지한다.

검증 결과는 기능 검사와 성능 측정을 구분한다. heartbeat 표본이 없으면 `0ms`가 아니라 `null / unmeasured`, 표본이 부족하면 `insufficient-samples`로 기록한다. 측정 파일에는 commit, 미커밋 여부, OS, 실제 DPI와 viewport를 포함한다. 2배 해상도로 저장한 이미지는 Windows 배율 200% 검증을 대신하지 않는다.

Windows 출시 검증에는 KO/EN 각각 실제 배율 100/150/200%, 최소 창 높이 480 DIP에서 로그·필터·선택 도구 동시 표시, 로그/텍스트/결과 단축키, 오프라인 UNC 선택·열기·테스트 취소, 프로필 교체 후 컬럼 너비 변경·재시작, 대용량 뒤쪽 정렬 페이지와 전체 내보내기를 포함한다. macOS 교차 빌드와 핵심 테스트가 통과해도 이 실행 검증을 완료한 것으로 기록하지 않는다.

## 지원 환경과 시작 방법

Windows 10/11 x64, .NET 10, WPF와 LePO.CO WPF-UI를 기준으로 개발한다. 소스 빌드에는 저장소의 `global.json`에 지정한 .NET SDK가 필요하다. Windows 7은 .NET 10의 지원 대상이 아니다. 원격 서버 연결과 앱 종료 후 실행되는 Windows 예약 작업은 현재 로컬 GUI의 기능 범위에 포함하지 않는다.

1. **홈**에서 구조화 보기를 연다.
2. 사용할 프로필을 선택한다. 처음에는 샘플 프로필을 사용하거나 프로필 옆 **JSON** 버튼으로 받은 프로필을 불러올 수 있다.
3. **위치** 버튼으로 탐색할 폴더·드라이브·공유 경로를 하나 이상 등록한다. 시작 경로는 프로필별로 최대 64개이며, 모든 경로의 결과를 중복 없이 하나의 목록과 프로필 DB에 모은다. 프로필 편집의 기본 정보에서도 목록을 관리할 수 있다.
4. **스캔 시작**을 누른다. 결과는 자동 저장되며 다음 실행에서 다시 불러올 수 있다.
5. 검색창에 단어를 입력하고 결과를 선택한다. 선택 항목 복사, 폴더 열기 또는 구조화 데이터 내보내기를 실행한다.

파일 찾기는 저장된 DB를 자동으로 확인한다. 구조화 보기에서 저장된 결과를 수동으로 다시 확인하려면 **데이터 관리 → 저장된 결과 불러오기**를 사용한다. DB 위치와 부분 새로고침은 **데이터 관리**, 파일 종류·크기·날짜·정렬은 별도의 **검색 조건** 패널에서 조정한다. 검색 조건 버튼에는 적용 중인 조건의 종류 수를 표시한다. 검색창이 기본 작업의 시작점이며, 이미 결과가 있으면 스캔 버튼을 **결과 새로고침**으로 표시한다.

홈은 현재 구성에 따라 위치 선택, 프로필 준비, 구조화 보기 중 다음 행동을 안내한다. 로컬 프로필을 준비한 뒤에는 프로필 테스트·출력 포맷 도구를 접힌 추가 영역에서 제공한다. 공유 결과는 새 프로필 작성보다 가져온 결과 조회를 우선한다. 부가 도구는 내비게이션에서도 계속 접근할 수 있다.

| 페이지 | 사용자가 하는 일 | 핵심 작업 공간 |
| --- | --- | --- |
| 홈 | 현재 구성과 다음 행동을 확인한다. | 구조화 보기 시작 동작 |
| 파일 찾기 (현재 숨김) | 이름·전체 경로·파일 메타데이터로 파일과 폴더를 찾는다. | 결과 표, 기능·데이터는 보존 |
| 구조화 보기 | 프로필로 추출한 업무 값을 검색하고 선택·편집·출력한다. | 동적 컬럼을 가진 결과 표 |
| 프로필 | 경로 조각 선택 또는 정규식 직접 작성으로 규칙을 정의한다. | 현재 편집 단계 |
| 프로필 테스트 | 저장된 프로필을 실제 경로에 적용한다. | 추출 결과 우선, 필요할 때 정규식 디버그 |
| 출력 포맷 | 선택한 항목을 복사할 템플릿을 정의한다. | 템플릿 편집과 예시 미리보기 |
| 설정 | 검색 처리량과 화면 모양을 조정한다. | 그룹별 설정 행 |

## 스캔과 검색 및 저장

**스캔**은 실제 파일 시스템을 방문해 DB를 갱신하는 작업이다. **불러오기**는 저장된 DB와 구조화 캐시를 열고, **검색**은 이미 확보한 결과에 조건을 적용한다. **부분 새로 고침**은 전체 검색 위치 아래의 지정한 폴더와 하위만 다시 스캔한다. **텍스트 컬럼 갱신**은 현재 프로필의 결과 전체에서 특정 컬럼의 파일 내용만 다시 읽는다.

파일 찾기의 스캔은 파일과 폴더의 이름, 절대경로, 크기, 생성일과 수정일을 저장한다. 구조화 스캔은 같은 탐색에서 폴더를 프로필로 해석하고 메타데이터와 추출 결과를 저장한다. 파일 찾기를 먼저 실행해야 구조화 보기가 동작하는 것은 아니다.

앱에서는 한 번에 하나의 스캔을 실행한다. 새 스캔 중에도 기존 게시 결과는 유지하지만, 작업 중인 페이지의 검색·정렬·선택·출력·파일 편집은 잠시 비활성화하여 화면 갱신에 집중한다. 취소와 페이지 이동은 계속 사용할 수 있으며, 비활성화 이유를 페이지에 표시한다. DB 자동 불러오기에는 이 스캔 잠금을 적용하지 않는다. 새 결과는 완료 후 게시하며, 취소한 작업이 이전 게시 결과를 덮어쓰지 않는다. 처음 스캔하는 경우에는 최대 500행의 실시간 미리보기를 표시한 뒤 완료 시 전체 결과의 페이지 조회로 전환한다. 목록과 진행 문구는 기본 10개 처리 단위로 묶고 UI에서는 최소 250ms 간격으로 병합하여 반영한다. 완료 시 남은 항목도 반영하며 DB에는 표시 주기와 관계없이 모든 결과를 저장한다. 설정의 화면 갱신 단위는 1–1,000개이며, 진행 중인 작업에는 시작할 때의 설정을 사용한다.

구조화 보기의 자동 불러오기는 저장된 구조화 결과만 확인한다. 결과가 없거나 현재 프로필·언어·인덱스와 맞지 않으면 확인 Dialog에서 실행 의사를 묻는다. 사용할 원본 인덱스가 있으면 **기존 인덱스로 만들기**, **새로 스캔**, **나중에**를 선택할 수 있고, 인덱스도 없으면 **스캔 시작** 또는 **나중에**를 선택한다. 동의 없이 전체 경로를 재해석하거나 디스크를 스캔하지 않는다. 기존 인덱스로 결과를 만드는 작업도 텍스트 컬럼의 파일을 읽을 수 있다. 취소한 자동 불러오기는 같은 작업 위치의 페이지에 다시 들어갔다고 재시작하지 않으며, 수동 실행 또는 작업 위치·프로필 변경으로 다시 시작할 수 있다.

DB가 여러 페이지에 걸쳐 읽히는 중 다른 작업이 결과를 바꾸면 서로 다른 시도의 행을 합치지 않는다. 기존 인덱스 분석은 이전 시도를 초기화하고 한 번 다시 읽는다. 재시도 중에도 데이터가 바뀌면 불러오기를 실패로 알린다.

루트와 DB를 바꿨다고 해서 이전 검색 결과가 새 위치의 결과가 되는 것은 아니다. 결과 표 바로 위에는 실제 검색 위치·저장/공유 여부·갱신 시각을 표시하고, 전체 출처와 DB 위치는 툴팁 및 데이터 관리에서 확인하며, 이전 결과를 유지할 때는 그 출처를 구분한다. 출력도 실제 결과의 출처를 기준으로 한다.

### 기본 저장 위치

기본 사용자 영역은 `%LOCALAPPDATA%\UCode\FindEverything.Gui`이다.

| 데이터 | 기본 위치 |
| --- | --- |
| 사용자 설정 | `appsettings.user.json` |
| GUI에서 작성한 프로필 | `Profiles\<profile-id>\profile.json` |
| 파일 찾기 인덱스 | `Indexes\metadata.db` |
| 프로필별 원본 인덱스 | `Indexes\Profiles\<안전한 ID와 해시>\db.db` |
| 구조화 결과와 사용자 입력값 | `results.db` |
| 컬럼 배치·복사 포맷·프로필별 선택 포맷 | `grid-layout.json`, `selection-output-formats.json`, `profile-output-preferences.json` |
| 가져온 공유 데이터 | `Imports\<source-id>\archive`, `Imports\<source-id>\linked-<revision>` |
| 마지막으로 선택한 데이터 원본 | `workspace-source.json` |

파일 찾기와 프로필별 DB 경로는 독립적으로 지정할 수 있다. 사용자 지정 경로가 없으면 프로필 ID로 기본 위치를 찾는다. 구조화 캐시는 프로필 정의, 검색 루트, 원본 DB, 인덱스 세대와 언어가 같은 경우에 재사용한다. 프로필을 수정하면 기존의 다른 규칙으로 만든 캐시를 그대로 사용하지 않는다.

메모는 프로필 ID·정규화된 절대경로·필드 ID에 연결한다. 재스캔과 재시작 후에도 같은 항목에 다시 연결하고, 한 셀을 바꿀 때 전체 메모 파일을 덮어쓰지 않는다. 기존 JSON 데이터의 자동 이전은 이번 정비의 필수 요구사항이 아니며, 이전 파일을 자동 삭제하지 않는다.

## 프로필이 경로를 업무 정보로 해석하는 방법

### 전체 절대경로

프로필 입력은 항상 **전체 절대경로**다. 검색 루트는 방문 범위만 제한한다. 예를 들어 `C:\Archive`와 `C:\Archive\Clients` 중 어느 위치를 검색 루트로 잡아도 같은 폴더의 프로필 입력은 `C:\Archive\Clients\A\Project-1\2026`이다.

매핑된 네트워크 드라이브는 규칙 적용 전에 UNC 경로로 변환한다. `Z:`가 `\\192.168.10.20\share`에 연결된 경우 `Z:\Clients\A`는 `\\192.168.10.20\share\Clients\A`로 전달한다. 공유가 호스트 이름으로 연결되어 있으면 그 호스트 이름을 사용하며, 임의로 IP 주소를 만들어 치환하지 않는다.

Windows의 `₩` 모양으로 표시되는 경로 구분자는 역슬래시 `\`를 뜻한다. 경로 작성과 초보자 조각 선택은 `\`와 `/` 구분자를 처리한다.

### 작성 단계

프로필 편집의 기본 흐름은 **프로필 정보 → 경로와 컬럼 → 검토와 저장**의 세 단계다. 폴더·파일 데이터, 외부 데이터 선택, 탐색 옵션은 선택 기능 메뉴에서 연다. 초보자 모드에서는 실제 경로를 분석하고 폴더·세부 조각 버튼을 눌러 컬럼에 연결한다. 필드를 먼저 선택하고 그 필드의 경로 조각을 지정하며, 드래그하거나 생성된 정규식을 직접 수정할 필요가 없다. 동일 경로를 다시 분석하면 기존 연결을 유지한다. 경로 조각 옆에서 연결할 컬럼과 선택된 원문 예시를 확인하며, 자동 생성된 규칙은 기본적으로 접는다. 경로 작성 모드는 경로 추출에만 적용되며, 모든 선택 기능이 정규식 없이 설정된다는 의미는 아니다. **저장하고 테스트**는 저장이 성공한 경우에만 프로필 테스트로 이동한다. 테스트 화면에서 다시 편집으로 돌아올 수 있고 기존 미저장 초안을 보호한다.

편집 초안은 단계 화면과 별도 세션에 보관한다. 현재 단계의 화면만 생성하므로 단계를 이동하거나 페이지를 다시 열어도 입력값은 유지된다. 단계 안의 설명·필드·규칙 카드는 하나의 스크롤 목록에 놓고, 화면 근처의 카드 컨트롤만 재활용해 필드 수에 비례하는 전체 렌더링을 피한다. 숫자 입력 오류는 즉시 표시하고, 입력에 따른 규칙 미리보기는 마지막 입력 후 300ms에 백그라운드에서 계산한다. 오래된 계산 결과는 새 입력을 덮어쓰지 않는다. 검증·저장은 미리보기가 끝날 때까지 기다릴 필요 없이 최신 초안을 사용한다.

전문가 모드는 정규식과 named group을 직접 입력한다. 하나의 패턴에서 여러 그룹을 추출하거나, 여러 경로 조각을 한 필드로 합칠 수 있다. 각 필드는 표시 이름·ID·값 종류·필수 여부·날짜 파싱 형식·표시 형식을 가진다. 경로 값이 없어도 되는 필드는 nullable로 설정한다. 필수 값 누락, 날짜·숫자 변환 실패와 제한 시간 초과는 오류로 구분한다.

컬럼 추가는 컬럼 섹션 맨 위에 배치해 경로 규칙 추가와 분리한다. 입력 형식과 표시 형식은 날짜/시간 타입일 때만 보인다. 단일 그룹·조합 그룹은 라디오로 선택하며 선택한 입력 하나만 표시하고, 방식을 바꾸면 다른 입력값을 초기화한다. 새 경로·폴더 제외·파일명 규칙 및 JSON의 생략된 `matchMode`는 부분 일치를 기본으로 한다. 명시적으로 저장한 전체 일치는 유지한다.

구조화 결과의 기본 정렬은 프로필에 정의된 첫 날짜/시간 컬럼의 내림차순이며 날짜 컬럼이 없으면 기존 기본 순서를 사용한다. 직접 선택한 정렬은 같은 프로필을 사용하는 동안 유지한다. 선택 체크박스와 폴더 탐색 버튼만 고정하고 모든 데이터 컬럼은 첫 컬럼부터 가로 스크롤한다. 헤더 체크박스는 현재 검색 결과의 전체 선택·해제를 수행하며 부분 선택에서는 전체 선택한다. 스캔 완료 소요 시간은 자동으로 사라지는 알림과 별도로 목록 상태줄에 유지한다.

초안에 변경 사항이 있으면 다른 프로필이나 포맷으로 이동하거나 앱을 종료·언어 재시작하기 전에 저장·버리기·취소를 선택한다. 저장 실패는 초안을 유지하며 계속 이동하지 않는다. 숫자 입력이 유효하지 않으면 설명을 표시하고 검증·저장을 막는다.

선택 기능 메뉴에는 폴더·파일 데이터, 외부 선택 규칙, 탐색 옵션에 정의한 항목 수와 현재 편집 중인 단계를 표시한다. 이 숫자는 초안의 설정 개수이며 검증 성공 표시가 아니다. 실제 저장 가능 여부는 검토 단계의 검증 결과로 판단한다.

### 날짜 결합 예시

입력이 `C:\Archive\2026\0521_Project\`이고 그룹이 `year=2026`, `monthDay=0521`인 경우, 두 값을 순서대로 합쳐 `20260521`을 만들고 `yyyyMMdd`로 파싱하면 `2026-05-21`의 DateTime이 된다. 연도·월·일이 각각의 폴더라면 `year`, `month`, `day`를 그 순서로 연결한다.

초보자 모드는 `연도 + 월일` 또는 `연도 + 월 + 일`과 예시 날짜를 선택하도록 한다. 전문가 모드에서는 C# 날짜 형식을 직접 지정한다. `2026 + 0230`처럼 달력에 없는 날짜는 성공으로 처리하지 않는다.

### 제외 규칙과 탐색 중단

| 설정 | 검사 대상 | 입력 예시와 결과 |
| --- | --- | --- |
| 폴더 이름 제외 | 절대경로의 마지막 폴더 이름 하나 | 전체 일치 패턴 `name`은 `C:\abc\def\name`에서 `name`만 검사한다. 해당 폴더와 하위를 건너뛰고 같은 부모의 다른 폴더를 계속 방문한다. 상위 `abc`, `def`는 검사하지 않는다. |
| 탐색 중단 그룹 | 경로 규칙의 지정한 캡처 그룹 | 필요한 그룹이 모두 비어 있지 않으면 일치 폴더 자체는 결과에 남기고 그 하위만 탐색하지 않는다. |

검색 루트는 사용자가 지정한 경계이므로 자신의 leaf 이름만으로 루트 전체를 제외하지 않는다. 제외 정규식의 제한 시간 초과는 경고로 남기고 탐색을 계속한다. 정확한 규칙 수·형식·제한 시간은 [프로필 작성 가이드](profile-authoring.md)에 정의한다.

### 텍스트 파일과 사용자 입력

텍스트 파일 필드는 파일명 정규식과 일치하는 **해당 폴더 바로 아래** 파일만 읽는다. 파일명이 정렬상 먼저인 첫 일치 파일을 사용하고, UTF-8 또는 BOM으로 식별 가능한 텍스트를 허용한다. 하위 폴더를 찾아 내려가지 않는다. 필드별 읽기 크기를 제한하고, 선택적 파일이 없으면 null로 처리한다. 파일 접근·인코딩·크기 오류는 규칙 외 결과와 구분한다.

긴 텍스트는 목록에서 처음 2,048자만 미리보기로 읽고 `…` 표시와 툴팁으로 알린다. 검색은 저장된 전체 내용을 대상으로 하고 복사·내보내기는 전체 값을 사용한다. 탐색 로그의 값 설명도 긴 필드 내용을 미리보기로 제한한다.

구조화 표의 텍스트 컬럼 헤더 옆 **갱신** 버튼은 필터나 선택과 무관하게 현재 프로필 결과 전체의 해당 컬럼만 다시 읽는다. 다른 컬럼·경로 규칙·하위 폴더 스캔은 실행하지 않는다. 완료 시 변경값을 게시하고, 취소하면 이전 값을 유지한다. 읽기에 실패한 셀은 이전 값을 보존하고 오류 아이콘과 설명을 제공한다. 저장된 캐시를 단순히 열 때는 텍스트 파일을 자동으로 다시 읽지 않는다.

사용자 입력 필드를 정의하면 행에 WPF-UI 텍스트박스가 나타난다. 입력 값은 검색·복사·CSV/XLSX에 포함된다. 입력 컨트롤을 클릭하거나 더블클릭한 동작을 행 선택이나 폴더 열기로 해석하지 않는다.

## 결과 검색과 선택 및 출력

### 셀 텍스트 선택과 컬럼 필터

구조화 값과 경로 셀은 선택 가능한 읽기 전용 WPF-UI TextBox이다. 셀 안에서 클릭·드래그하면 텍스트에 포커스를 주고 선택하며, `Ctrl+C`는 선택한 텍스트를 복사한다. 텍스트 영역 바깥의 행 여백을 클릭하면 체크박스에 포커스를 주고 항목 선택을 한 번 토글한다. TextBox 밖의 `Ctrl+C`는 체크한 항목을 현재 출력 포맷으로 복사한다. 사용자 입력 컬럼만 로컬 결과에서 편집할 수 있다. 공유 데이터의 사용자 입력값은 읽기 전용이다.

컬럼 제목 클릭 또는 Enter/Space는 오름차순·내림차순 정렬을 전환한다. 제목 옆 필터 아이콘 또는 F4로 타입별 필터를 연다. 활성 필터 칩의 본문은 편집, X는 삭제다. 텍스트·경로는 포함/미포함, 정수·소수는 최소/최대 범위, 날짜는 시작일/종료일, Boolean은 참/거짓을 선택한다. 날짜 종료일은 해당 날짜 전체를 포함한다. 선택한 날짜는 버튼에 현재 언어의 날짜 형식으로 표시하고, 각각의 제한을 해제할 수 있다. 숫자 슬라이더 옆 입력란은 Decimal 정밀도를 유지하며, 유효하지 않은 범위는 마지막 유효 조건을 유지한다. Nullable 값은 값 없음/값 있음을, 텍스트는 빈 텍스트 여부를 따로 선택할 수 있다. 일반 값 비교는 누락값을 제외한다.

여러 컬럼 조건과 통합 검색은 AND로 결합하며 연속 입력은 마지막 입력 후 700ms에 자동 적용한다. 파일 찾기 검색창·구조화 통합 검색창·컬럼 필터의 연속 입력은 같은 디바운스를 사용하며, 새 입력이 오면 이전 대기와 조회를 취소한다. 정렬·조건 삭제·명시적 불러오기는 입력 지연 없이 수행한다. 활성 조건을 개별 삭제하거나 전체 해제할 수 있다. Enter는 검색창의 대기 중 입력을 즉시 적용한다. 검색 조건·정렬을 바꾸어도 체크한 항목을 유지하며, 하단에 전체 선택 개수와 현재 결과 안의 선택 개수를 구분한다. 검색으로 가려진 항목도 복사·내보내기에 포함된다. 전체 선택 상태를 다른 검색으로 옮길 때는 선택 키를 임시 SQLite에 고정하므로 전체 행을 메모리에 적재하지 않는다. 보존 작업 중에는 취소와 검색어 입력을 허용하되 선택·출력 동작은 잠시 잠근다. 새 조건은 이전 조회를 실제 SQLite interrupt/progress 처리로 중단한다. 스캔 저장 연결은 중단하지 않는다.

### 프로필·인덱스 파일 공유

구조화 보기의 프로필 옆 **JSON** 버튼으로 프로필을 직접 가져올 수 있다. 페이지 상단 데이터 원본·공유 메뉴에서는 프로필 JSON 또는 `.fepkg`를 열거나 파일을 드롭할 수도 있다. JSON은 검증 후 LocalAppData에 설치하며 전용 JSON 버튼으로 가져온 프로필은 바로 선택한다. 같은 ID가 있으면 새 프로필/교체/취소를 선택하고, 기본값인 새 프로필은 기존 정의와 데이터를 보존한다. 취소하거나 실패하면 기존 선택을 유지한다. DLL 프로필은 가져오거나 JSON으로 내보내지 않는다. Windows 전체 `.json` 연결 프로그램 등록도 하지 않는다.

내보낸 프로필 JSON의 선택적 `workspace`에는 프로필 전용 출력 포맷, 현재 선택한 복사 포맷, 컬럼 너비 프리셋·수동 너비·표시 여부를 함께 담는다. 선택한 공용 사용자 포맷도 프로필용 사본으로 포함한다. 경로 규칙·날짜 형식·값 매핑·파일 컬럼·외부 선택·탐색 조건 등 기존 프로필 정의는 그대로 포함한다. 가져올 때 출력 포맷 ID를 새로 부여해 다른 프로필의 포맷을 덮어쓰지 않는다. 표시·출력 설정은 파싱 캐시 식별자에 포함하지 않는다.

앱은 실행 중 표시·출력 설정을 별도 저장소에 저장하며, **프로필 JSON 내보내기**가 최신 설정을 모아 하나의 이동 가능한 스냅샷을 만든다. LocalAppData의 `profile.json`을 직접 복사하면 내보내기 이후 변경된 표시·출력 설정은 빠질 수 있다. DB, 행별 메모, 이 PC의 루트·DB 경로, 현재 검색 조건, 언어·테마 같은 앱 전역 설정은 JSON에 넣지 않는다.

`.fepkg` v2 (v1 읽기도 지원)은 위 표시·출력 설정을 포함한 한 JSON 프로필과 한 루트의 게시된 파일 메타데이터, 선택적인 구조화 결과를 담은 ZIP 패키지다. 메모·사용자 입력값은 기본 제외이며 사용자가 선택할 때만 포함한다. 공용 결과 DB 전체, 다른 루트, 스캔 staging 데이터, DLL, 앱 전역 설정은 포함하지 않는다. 구형 패키지의 별도 컬럼 설정은 JSON에 `workspace`가 없을 때만 적용한다. 메타데이터와 구조화 결과의 스캔 ID나 현재 프로필 정의가 맞지 않으면 구조화 결과를 함께 내보내지 못하며, 사용자가 선택하여 메타데이터만 내보낼 수 있다.

원본 파일·폴더와 텍스트 파일이 없어도 가져온 구조화 값의 조회·필터·정렬·복사·CSV/XLSX 내보내기는 가능하다. 파일 찾기는 공유된 메타데이터 범위만 보여준다. 폴더 중단·제외 규칙이 적용되었을 수 있으므로 공유 결과를 디스크의 모든 파일이라고 해석하지 않는다. 구조화 결과가 없는 패키지는 해당 페이지에 ‘구조화 결과 미포함’을 표시하고 자동으로 재파싱하거나 스캔하지 않는다.

가져올 때 원래 루트에 한 번 연결을 시도한다. 연결할 수 없거나 네트워크 확인이 지연되면 이 PC의 해당 폴더를 연결하거나 오프라인 조회를 선택할 수 있다. 연결된 경로는 화면 표시·검색·정렬·열기·복사에 동일하게 적용하고, 원래 경로는 툴팁과 `{OriginalFullPath}` 출력 토큰으로 보존한다. 연결해도 기존 구조화 값은 재파싱하지 않는다. 항목 identity와 포함된 메모는 원본 경로를 기준으로 유지한다.

공유 데이터는 원본을 보관하고 앱 전용 조회 DB를 만드는 읽기 전용 데이터 원본이다. 루트를 다시 연결하면 원본에서 새 조회 DB를 만들고 현재 선택을 초기화한다. 재스캔·부분 갱신·텍스트 컬럼 갱신·메모 편집은 허용하지 않는다. 새 구조화 결과는 로컬 결과로 전환하여 명시적으로 스캔해야 한다. 절대경로 규칙이 새 루트에도 맞는지는 Playground에서 확인한다. 패키지 버전·DB 식별자·스키마·파일 해시·데이터 정합성을 검사하며 손상·경로 탈출·중복 항목·미지원 버전은 거부한다. 해시는 손상 검사용이며 발신자의 신원을 보장하지 않는다.

파일 찾기는 파일명·전체 경로의 키워드, 파일·폴더 구분, 파일 크기, 생성일과 수정일을 사용한다. 크기 조건은 파일에만 적용하고 폴더는 해당 결과에서 제외한다. 화면의 **종류** 정렬은 PDF·ZIP 등 표시한 파일 형식과 일치한다.

구조화 검색은 컬럼과 전체 폴더 경로를 함께 검색한다. 여러 단어를 입력하면 모든 단어가 있는 항목을 남기고 일치한 키워드를 강조한다. 값 매핑이 `A → 홍길동`이면 치환된 값을 기본으로 표시하고 원본이 있음을 `↔`로 알린다. **원본 값 표시 (화면만)**는 셀 표시만 바꾼다. 검색·정렬·선택 항목 복사·내보내기는 항상 치환 값을 사용한다. 셀 안에서 직접 드래그한 텍스트를 복사할 때는 보이는 원문을 복사한다.

결과 행의 체크박스와 행 선택은 같은 도메인 선택을 표현한다. 두 결과 페이지 모두 일반 행 클릭으로 체크를 토글하고 다른 행의 선택을 유지하며 Shift로 범위를 선택한다. **전체 선택**과 Ctrl+A는 아직 화면에 읽지 않은 결과를 포함한다. 전체 선택·해제·반전은 모든 행을 메모리에 올리지 않고 표현한다. 검색 조건과 정렬 변경은 선택을 유지한다. 루트·프로필·게시 세대처럼 데이터의 정체성이 바뀌면 선택을 해제한다. 체크박스 헤더는 현재 검색 결과 전체 선택/해제이며, 현재 결과만 해제할 때 다른 검색에서 체크한 항목은 유지한다. 하단의 전체 선택 해제는 숨겨진 선택까지 해제한다.

행의 우클릭 메뉴에서 폴더 열기·경로 복사를 사용할 수 있다. 행 메뉴는 클릭한 행에 적용되고 선택 항목 복사·내보내기는 선택 전체에 적용된다. 단일 선택의 폴더 열기를 제공하고, 여러 항목을 한꺼번에 열지는 않는다. 선택 도구는 표 아래의 전용 공간을 사용해 마지막 행과 스크롤바를 덮지 않는다. 선택 관리와 출력 작업을 좌우로 구분하며, 복사 버튼의 화살표(F4/Alt+↓)에서 출력 포맷을 고른다. 행별 열기 동작은 우클릭 메뉴나 Enter를 사용하며 여러 선택 중 임의 한 행을 열지 않는다.

출력 포맷은 `{FullPath}`, `{FolderPath}`, `{Name}`, `{Field:필드ID}` 등의 토큰과 항목 사이 구분자를 조합한다. 사용할 구조화 프로필을 선택하면 해당 컬럼의 버튼이 나타나며, 클릭하면 표현식의 커서 위치에 토큰을 넣거나 선택한 텍스트를 치환한다. Prefix와 Suffix는 각 항목이 아니라 전체 복사 결과에 한 번씩 붙인다. 예를 들어 Prefix `[`와 Suffix `]`, 구분자 `, `를 사용하면 `[첫 항목, 다음 항목]`이 된다. 선택 항목이 없으면 앞·뒤 문구만 복사하지 않는다. Ctrl+C는 현재 포맷과 정렬 순서대로 복사한다. 텍스트박스를 편집 중일 때는 일반적인 텍스트 복사를 우선한다. 포맷 페이지는 편집과 미리보기를 함께 보여주며 좁은 창에서는 위아래로 배치한다. 기본 포맷은 비활성 폼 대신 읽기 전용 설명과 복사본 만들기를 제공한다. 미리보기는 예제 두 항목 또는 최근 같은 프로필 테스트의 실제 값 한 항목을 사용하고 출처를 명시한다. 실제 테스트 값은 메모리에만 보관하며 타이핑 중 디스크를 다시 읽지 않는다. 긴 출력 미리보기는 16,384자로 제한하지만 실제 복사 결과를 자르지 않는다.

구조화 내보내기는 실제 `.xlsx` 또는 UTF-8 `.csv` 파일을 만든다. 출력 시작 시점의 선택·정렬·값 기준으로 데이터를 스트리밍한다. 임시 파일에서 쓰기를 마친 뒤 목적지에 게시하므로 오류·취소가 기존 파일을 부분 출력으로 덮어쓰지 않는다. Excel 행·열·셀 제한과 클립보드 크기 제한을 넘으면 명확히 알린다.

선택 항목이 있으면 두 결과 페이지의 **선택 항목만 보기**로 현재 검색에서 숨겨진 체크까지 검토할 수 있다. 검토 중에는 검색 조건을 잠시 적용하지 않고 편집을 잠그며, 닫으면 기존 조건으로 돌아온다. 검토 중 체크를 해제하면 목록에서도 빠지고, 마지막 항목을 해제해도 검토 종료 동작은 남는다. 복사 버튼에는 현재 출력 포맷 이름을 함께 표시하고 긴 이름은 툴팁으로 확인한다.

구조화 선택 검토는 DB의 선택 집합 구간 조회를 사용한다. 파일 선택 검토는 작업 스레드에서 체크된 메타데이터를 임시 SQLite로 스트리밍한 뒤 필요한 구간만 읽는다. 준비 중에는 이전 결과를 유지하고 선택 작업을 잠시 막으며 준비를 취소할 수 있다. 전체 선택 결과를 UI 메모리에 한꺼번에 올리지 않지만, 파일 선택량이 크면 최초 준비에 시간이 걸릴 수 있다. 임시 검토 DB는 세션 해제 시 정리한다.

## 디자인과 접근성 요구사항

구조화 보기의 기본 명령 영역은 두 줄이다. 첫 줄은 강조된 검색창·스캔·데이터 관리·취소, 둘째 줄은 프로필·JSON 불러오기·검색 위치·공유 원본이다. 진행 문구와 결과 출처는 결과 바로 위의 고정 높이 한 줄에서 교대하며, 긴 문구는 말줄임과 전체 내용 툴팁을 사용한다. 취소 버튼 자리도 미리 확보해 작업 중 검색창 너비가 변하지 않게 한다. 활성 컬럼 필터는 여러 줄로 접히지 않는 가로 스크롤 영역에서 확인한다. 좁은 창에서는 보조 버튼의 텍스트만 접고 아이콘·툴팁·접근성 이름을 유지한다.

모든 페이지는 **명령 영역 → 핵심 작업 공간 → 필요한 선택 작업**의 동일한 흐름을 사용한다. 현재 위치는 내비게이션으로 구분하고 페이지 제목을 크게 반복하지 않는다. 결과의 출처·대기 상태는 결과 가까이에 표시하며 중복 상태줄은 두지 않는다. Fluent의 간격·타이포그래피·색상 규칙을 기반으로 PowerToys 설정 화면처럼 작은 명령줄과 관련 설정을 묶은 카드를 사용한다. 설명 카드가 결과보다 큰 영역을 차지하지 않게 한다. 구조화 표의 고정 선택 컬럼은 64 DIP이며, 체크박스 양옆에 충분한 여백을 두어 가로 스크롤과 좁은 창에서도 잘리지 않게 한다.

작업 결과 알림은 내비게이션을 제외한 페이지 하단 우측의 중립색 플로팅 InfoBar로 표시한다. 최대 너비는 480 DIP이며, 페이지·결과 표의 높이를 줄이지 않고 하단 액션과 열린 로그 위에 표시한다. 알림 바깥은 클릭을 통과시킨다. 일반 결과 알림은 기본 3초 후 자동으로 사라지며 닫기 버튼으로 즉시 제거할 수 있다. 오류는 자동으로 사라지지 않고 사용자가 닫는다. 포인터 또는 키보드 포커스가 알림 안에 있으면 자동 닫기를 일시 정지한다. 제목 표시줄의 알림 메뉴에서 최근 30개 이력과 상세 복사를 제공한다. 표시 시간은 설정에서 1–60초로 바꾼다. 새 알림은 표시 시간을 다시 시작하고, 이전 알림의 타이머가 새 알림을 닫지 않는다. 입력 검증과 현재 진행 상태는 해당 페이지에 계속 표시한다.

콘텐츠·명령줄·빈 상태는 WPF-UI의 네이티브 카드로 묶고, 장식 배지는 별도의 비대화형 표시 컨트롤을 사용한다. 카드 내부 여백은 16 DIP, 툴바는 12 DIP, 관련 컨트롤 간격은 8 DIP다. 각 페이지는 내비게이션과 중복되는 큰 제목 없이 검색·편집 등 작업 영역부터 시작한다. 공유·새 포맷·테스트·진행 표시를 제목 제거와 함께 없애지 않고 해당 작업 영역에 둔다. 선택 메뉴는 왼쪽에 선택 관리, 오른쪽에 복사·내보내기를 배치한다. 실제 페이지 너비가 1040 DIP보다 작으면 선택 관리를 메뉴로 접는다. 출력 포맷은 복사 분할 버튼의 메뉴에서 선택하며 복사·내보내기는 작은 창에서도 직접 실행한다.

콤보박스는 선택된 표시 문자열과 글꼴·배율을 기준으로 너비를 확보한다. 프로필·출력 포맷처럼 이름이 긴 선택은 다른 입력과 좁은 열을 나눠 쓰지 않도록 배치한다. 설정의 선택 입력은 주어진 너비를 채운다. 아주 긴 이름은 화면과 할당된 열의 너비 안에 제한하고 전체 선택값을 툴팁으로 확인할 수 있게 한다. 너비 계산을 위해 전체 선택 목록이나 검색 결과를 순회·실체화하지 않는다.

프로필의 각 컬럼은 좁게·기본·넓게 표시 프리셋을 가진다. 화면과 컬럼 수에 맞춰 초기 너비를 분배하고 이미 로드된 최대 200행만 내용 측정에 사용한다. 스크롤 시 너비를 다시 측정하지 않으며, 긴 값은 줄임표와 툴팁으로 표시한다. 수동 너비와 컬럼 표시 여부를 프로필별로 보존하고 표시할 컬럼 메뉴에서 모두 표시·너비 초기화를 제공한다. 첫 식별 컬럼은 항상 표시하되 고정하지 않으며 다른 데이터 컬럼과 함께 스크롤한다. 컬럼의 기본 순서는 프로필 정의 순서를 따른다. 표시 설정은 Desktop의 별도 `presentation.json`에 저장하여 규칙·캐시 식별자·기존 DB에 영향을 주지 않는다.

언어 변경은 **지금 재시작 / 나중에 적용 / 취소**로 결정한다. 지금 재시작은 미저장 초안을 보호하고 활성 작업 중에는 차단한다. 나중에 적용은 설정과 적용 대기 표시만 남기며 작업이 끝났다는 이유로 자동 재시작하지 않는다. 생성된 화면 문자열과 진행 상태까지 한 언어로 구성하는 현재 정책을 유지한다. 기본 Light/Dark 테마, 고해상도 DPI, 작은 창에서 같은 동작을 제공한다.

설정의 미저장 변경도 종료·언어 재시작 전에 저장·버리기·취소로 보호한다. 숫자 검증 실패와 저장 실패는 이동을 막고 입력을 유지한다. 설정 저장 중에는 종료하지 않으며 외부 설정 갱신이 편집 중인 입력을 덮어쓰지 않는다. 언어를 나중에 적용하기로 한 앱 내부 설정 저장을 파일 감시자가 외부 변경으로 오인해 재시작하지 않는다.

데이터 관리와 검색 조건 패널은 한 번에 하나만 열고, 스크롤 영역 밖에 닫기 버튼을 둔다. Escape는 열린 콤보박스·달력부터 닫고 다음 Escape로 패널을 닫는다. 패널을 닫으면 열었던 버튼으로 키보드 포커스를 돌려준다. 좁은 창에서 패널은 페이지 안에서만 겹치며 내비게이션을 가리지 않는다.

## 프로젝트 구조와 확장 계약

```text
Desktop → Application → Profile.Abstractions
   ├────→ Profile.Runtime → Profile.Abstractions
   ├────→ Infrastructure.Persistence → Application
   └────→ Infrastructure.FindEverything → Application + Engine submodule

업무 DLL → Profile.Abstractions
선언형 profile.json → Profile.Runtime에서 검증과 컴파일
```

Application은 프로필 계약과 결과 조회·저장 계약을 정의한다. Profile.Runtime은 선언형·DLL 프로필 로딩, 검증, 정규식 컴파일과 값 매핑을 구현한다. 엔진 어댑터는 원본 인덱스와 파일 시스템 탐색을 연결하고 Persistence는 구조화 결과·셀 값·메모를 SQLite에 저장한다. WPF, Windows API와 화면의 명령 연결은 Desktop에 둔다. Generic Host·DI·IOptions로 구현을 조합하며 업무 DLL은 Host 서비스 등록이나 UI 타입에 의존하지 않는다.

조회 세션은 쿼리와 결과 세대를 고정하고 전체 개수, 구간 읽기, 선택 결과 비동기 열거를 제공한다. 기본 페이지는 500행이다. 전체 선택은 `전체 일치 항목과 제외 키` 또는 `명시적으로 선택한 키`로 표현한다. 대용량 Catalog 호출은 각 성공 행을 writer에 전달하고 전체 모델 목록을 반환하지 않을 수 있으며, 총 일치·오류 건수는 상세 목록의 길이와 독립적으로 유지한다.

조회는 첫 페이지와 전체 개수 계산을 분리한다. 첫 결과가 도착하면 스크롤·개별 선택·복사를 사용할 수 있고, 전체 개수가 확인되기 전에는 전체 선택·선택 반전을 잠시 비활성화한다. 개수 계산을 취소하거나 계산만 실패해도 이미 받은 행과 선택을 유지한다. 파일 찾기는 건수 옆 재시도 버튼으로 재스캔 없이 조회를 다시 수행할 수 있다. 검색어 입력에만 지연을 적용하며 명시적인 불러오기·정렬에는 입력 지연을 추가하지 않는다. 외부 데이터로 선택한 행의 체크 상태는 백그라운드 일괄 조회로 확인한다.

취소한 스캔의 미게시 DB 세대 정리는 작업 스레드에서 끝까지 기다린다. 정리 중에도 UI 입력을 처리하며, 정리가 실패해도 실행 중 표시가 남지 않는다. 작업 완료·취소의 마지막 진행 상태를 제외한 중간 진행 알림은 기본 250ms 단위로 병합한다. 느린 UI 처리 중 들어온 알림은 최신 값만 유지하고, 처리가 끝난 뒤 다음 간격을 시작해 밀린 갱신이 연속 실행되지 않도록 한다. 중간 결과가 달라지지 않은 진행률 알림은 전체 표를 다시 필터링하지 않는다.

탐색 로그는 생산자 측에서 최근 최대 20,000줄을 보관한다. 닫힌 패널에는 행 변경을 보내지 않으며 열린 패널에는 200ms 주기로 변경을 묶어 반영한다. 로그 저장은 아직 화면에 반영되지 않은 보관분도 포함한 클릭 시점 스냅샷을 백그라운드에서 쓴다. 이는 전체 세션의 무제한 로그 저장이 아니며 이전 보관분 생략 안내를 유지한다. 자동 스크롤을 끈 경우 배치 갱신 후에도 선택과 보관 범위 안의 읽던 위치를 유지한다.

구조화 결과의 읽기 전용 셀은 유휴 상태에서 단순 텍스트만 그리고, 첫 포인터·키보드 입력 시 실제 TextBox 텍스트 뷰를 만든다. 드래그 선택·복사와 접근성 값은 유지한다. 강조할 단어가 없으면 rich-text Inline 트리를 만들지 않고, 오류가 없는 셀에는 경고 UI를 만들지 않는다. 페이지 전체의 슬라이드·페이드 전환은 사용하지 않는다.

앱은 Shell과 Home부터 구성하고 나머지 페이지를 첫 방문 때 생성한다. `IPageSession`은 자동 조회와 표시 작업의 활성화·취소를 관리하며, 직접 시작한 스캔은 앱 작업 세션이 소유한다. 비활성 화면은 변경된 상태를 기록했다가 다음 방문에 반영한다. Shell은 가벼운 활동 상태만 구독하므로 진행 표시를 위해 결과 페이지 전체를 만들지 않는다.

프로필 저장은 Application의 작성 workflow, Persistence의 JSON repository, Runtime의 컴파일로 역할을 나눈다. 파일 잠금·변경 충돌 확인·임시 파일 재검증·원자적 교체는 유지한다. WPF 화면에는 입력 상태와 진단 표시를 남기고, Playground의 경로 평가도 UI와 무관한 Application 서비스에서 수행한다. 기존 프로필 계약 4와 JSON·DB·공유 패키지의 저장 형식은 변경하지 않는다.

프로필의 `ReadTextColumn` 계약은 한 컬럼만 읽는 결과와 오류를 반환한다. 경로 재매핑이나 다른 필드의 평가를 대신 실행하지 않는다. 엔진의 기존 CLI·서버 API와 파일·폴더 종류 정렬을 유지하면서 화면용 파일 형식 정렬을 추가한다.

## 검증과 배포

설정의 구조화 보기 행 밀도는 좁게/보통/넓게이며 기본값은 보통이다. 행 본체 높이는 36/44/56 DIP, 행 사이 간격은 2/4/8 DIP이고 셀 Padding·편집기 여백도 같이 바뀐다. 체크박스는 24 DIP와 고정 선택 컬럼 공간을 유지한다. 설정 저장 후 화면에 적용하며 재조회·재스캔을 실행하지 않는다.

간격은 [Fluent 2 레이아웃](https://fluent2.microsoft.design/layout)과 [React spacing 토큰](https://raw.githubusercontent.com/microsoft/fluentui/master/packages/tokens/src/global/spacings.ts)을 WPF DIP 리소스로 옮겨 사용한다. 4 단위 기본 ramp와 아이콘 정렬용 2·6·10을 구별한다. 실제 대응 타입이 있는 컨트롤은 Wpf.Ui.Controls를 사용하고, 라이브러리에 없는 ComboBox·CheckBox·Slider 등은 WPF-UI 리소스로 테마를 적용한다.

자동 테스트는 초안 보존, 숫자 검증, 반복 경로 분석, 절대경로·UNC·날짜, 제외·탐색 중단, 세대 변경·재시도·취소, 부분 스캔, 메모 보존, 전체 선택·출력, 텍스트 컬럼 갱신을 포함한다. WPF 구성 테스트는 페이지 로드, 스크롤 공간, 선택 도구와 결과 표의 비중, 입력 컨트롤의 더블클릭 구분을 확인한다.

Windows에서는 실제 마우스·키보드·포커스, KO/EN, Light/Dark, 100–200% DPI와 최소·중간·기본 창 크기를 검증한다. 대용량 성능은 준비된 DB에서 응답 시간·캐시 행 수·메모리·WAL을 함께 측정한다. Windows CI는 Release 빌드·전체 테스트와 win-x64 배포 패키지 생성을 확인한다.

UI 성능 비교 워크플로는 같은 Windows runner에서 이전 버전과 현재 버전에 동일한 10만 행·20컬럼 및 10만 로그 fixture를 적용한다. `performance-baseline.json`과 `performance-current.json`에 UI heartbeat 지연 P95·최대값, 할당량, placeholder·목록 알림 수를 기록한다. 공유 runner의 시간 수치는 비교 근거로 사용하고, 기능 테스트는 캐시 한도·취소·요청 슬롯에 비례한 알림 등 결정적인 조건을 검증한다. 이 fixture는 파일 시스템이나 실제 DB 처리량을 측정하는 벤치마크는 아니다.

`performance-pages-*.json`은 실제 Shell·프로필 페이지에서 첫 진입·재진입·6단계 이동·20컬럼 초안의 연속 입력과 타입 변경을 측정한다. 단계별 visual 수와 UI 스레드 할당량을 함께 기록한다. 입력 측정은 실제 화면에 연결된 ViewModel의 변경을 재현하며 네이티브 키보드 왕복 시간 측정과는 구별한다. 각 입력 사이의 5ms 대기와 화면 배치·렌더링을 위한 공통 20ms 대기를 포함하고, 마지막 입력 이후 지연 실행되는 미리보기 완료 시간은 입력 구간과 구분한다. `HeartbeatSampleCount`가 0인 구간의 지연값 0은 측정값 없음이며 지연이 없다는 뜻이 아니다. 비교 기준 커밋은 워크플로 입력으로 지정하고, 동일 fixture를 양쪽에 적용한다.

### 2026-10-15 추가 응답성 개선의 검증 상태

## 폴더·외부 데이터·실제 파일 작업

GUI는 프로필 계약 v4로 저장하며 기존 v2/v3 읽기를 지원한다. v3 기능을 v2로, 컬럼별 선택 Regex AND 조건을 v2/v3으로 선언하면 검증에서 거부해 이전 앱이 조용히 설정을 무시하지 않게 한다. 기존 사용자 설정의 계약 버전 2/3은 로딩 시 현재 버전으로 정규화한다. 프로필 검증 오류는 지속되는 빨간 오류 목록과 해당 단계로 이동하는 버튼으로 안내한다.

폴더 존재 Boolean 컬럼은 일치한 폴더 **바로 아래**에서 지정한 고정 이름의 폴더를 확인한다. 기본은 대소문자 무시이며 자손 전체를 탐색하지 않는다. 존재하면 true, 없으면 false이고, 권한·네트워크 오류는 null과 컬럼 오류로 표시한다. 필요한 이름만 보관하므로 하위 폴더 수만큼 메모리를 늘리지 않는다. 텍스트 파일 누락·읽기 실패도 경로가 일치한 행을 유지하며 컬럼 확인 필요 항목 수를 따로 집계한다. 경로 캡처·타입 변환 오류는 여전히 파싱 실패다.

프로필의 최대 스캔 레벨은 검색 루트 0, 직속 하위 폴더 1을 기준으로 기본 256, 허용 0–1024이다. 경계 폴더는 판정하지만 하위 탐색을 중단한다. 부분 탐색도 전체 루트를 기준으로 계산한다. 새 스캔에만 적용하고 저장 결과 조회·기존 인덱스 재해석에 소급 적용하지 않는다. 경계 폴더의 직접 지정한 파일 읽기·폴더 존재 확인은 수행할 수 있다.

**데이터로 선택**은 XLSX 파일, HTML 표, 텍스트·CSV·TSV·다중 행 정규식 추출을 지원한다. 프로필 규칙이 입력 헤더·열 번호·그룹 이름을 안정적인 FieldId에 연결한다. 한 입력 행의 컬럼은 AND, 입력 행끼리는 OR이고 기본 비교는 표시값이다. 문자열은 앞뒤 공백·대소문자를 무시하며 날짜는 기본적으로 날짜 부분을 비교한다. 미리보기에서 오류·미일치·중복·다중 항목 일치를 확인한 뒤 적용하면 현재 필터를 만족하는 전체 결과의 체크를 교체한다. 빈 값은 wildcard가 아니며, 적용·취소 전에 기존 체크를 바꾸지 않는다. 클립보드는 감시하지 않고 이후 스캔 행에도 계속 적용하지 않는다.

컬럼별 정규식 조건은 추출 이전의 게이트다. 같은 행의 모든 정규식이 일치하고 모든 지정 그룹이 존재해야 캡처를 비교한다. Table/TextLines는 선택한 셀, 컬럼별 Regex 입력은 전체 한 줄에 적용한다. 기존 공통 패턴만 있는 입력은 다중 행 `Regex.Matches` 의미를 유지한다. 미리보기 입력 행 수는 정규식을 통과한 행 수다. 구조화 표는 프로필 순서로 생성하고 오래된 저장 위치로 순서를 덮어쓰지 않는다. 수동 너비는 보존한다. 헤더 팝업은 내부 컨트롤 입력·외부 클릭 닫기·Escape를 지원한다. 행의 … 버튼은 실제 폴더 트리를 열며 파일 클릭/Enter는 기본 프로그램으로 연다.

매칭은 DB에서 수행하고 대량 선택은 별도 임시 SQLite 키 집합으로 보관한다. 미로딩 결과도 체크·전체 선택·반전·복사·내보내기에 반영하며 공유 데이터는 원본 경로 identity를 유지한다. 파싱 입력과 미리보기에는 크기·행 수 상한이 있고 초과 시 명확히 중단한다. HTML 외부 리소스·스크립트와 Excel 수식은 실행하지 않는다. 프로필·검색 조건·결과 세대가 바뀌면 적용을 중단한다. Playground에서는 저장된 규칙으로 입력을 해석하고 이미 테스트한 샘플 한 행과만 비교한다.

구조화 표의 완료/대기 상태 컬럼은 제거하고 고정 너비의 **… 탐색 버튼**으로 교체한다. 버튼은 실제 디렉터리를 사용자 클릭·펼침 시 비동기로 읽는 TreeView Flyout을 연다. 인덱싱하지 않으며 닫기·행 전환 후 늦은 결과를 무시한다. 연결 폴더는 자동 재귀 탐색하지 않고 경로 복사·새로고침·탐색기 열기를 제공한다. 탐색·편집 버튼 클릭은 행 체크를 토글하지 않는다.

텍스트 파일 편집은 프로필이 허용한 로컬 컬럼에서만 가능하다. 새 GUI 컬럼은 허용을 기본으로 하고 기존 v2/null 설정은 읽기 전용이다. 누락 파일에는 생성, 실제 파일에는 수정 버튼을 표시하며 **빈 파일은 누락으로 해석하지 않는다**. 별도 편집창에서 대상 경로·전체 내용을 확인하고 저장해야 디스크를 변경한다. 생성 이름은 고정 이름 또는 `{Field:필드ID[:형식]}`, `{RandomGuid}` 표현식이며 읽기 정규식과 일치해야 한다. 경로 탈출·잘못된 이름·링크 경유 쓰기·기존 파일 덮어쓰기 생성은 거부한다. 기존 인코딩·BOM·줄바꿈을 유지하며 외부 변경은 덮어쓰지 않는다.

실제 파일 쓰기와 한 셀의 캐시 갱신은 공통 쓰기 작업 안에서 수행한다. 결과 전체를 복제하지 않고 셀과 조회 revision을 트랜잭션으로 갱신해 이전·새 값을 섞어 읽지 않는다. 다른 체크는 유지하고 필터에서 벗어난 수정 행만 선택에서 제거한다. 디스크 저장 성공·캐시 갱신 실패는 구분해 알린다. 파일 찾기의 메타데이터 목록은 별도 새로고침 전까지 기존 인덱스이며 공유 데이터는 파일 편집 불가다.

자동 선택·파일 생성 설정·최대 깊이만 바뀌어도 저장된 구조화 값은 무효화하지 않는다. 파싱·파일 읽기 규칙이 바뀐 경우에는 기존 확인 Dialog와 명시적 재생성 절차를 사용한다. DB v3은 파일 존재 상태와 파일명·인코딩·버전 정보를 저장하며 기존 v2 DB의 값은 보존해 업그레이드한다. 출처 정보가 없는 예전 결과는 생성 여부를 추측하지 않고 해당 컬럼을 다시 읽어 확인한다.
